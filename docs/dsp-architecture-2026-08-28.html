KURV realtime DSP architecture

What runs where, what “per voice” means, which optimizations survived measurement, and which experiments were deleted.

Signal ownership

Control/UIPublishes bounded parameters, graph edits, and immutable source data.
Audio callbackAdvances smoothers and control frames. No allocation, locks, I/O, or rendering.
Polyphonic noteOwns independent oscillator, modulation, filter, envelope, and noise history.
Ordered groupUnison sums inside each oscillator; later generators may consume earlier PM; filters process the note's stereo sum.
Host outputNote voices sum, then group gain/pan and output-pair routing apply.

Per voice means per polyphonic note, not per unison lane. A filter after each unison lane would multiply state and CPU. A filter after all notes are summed would be cheaper but would destroy note-specific modulation and couple every note through one state.

Audio-rate modulation boundary

Generator PM is ordered, same-group, earlier source to later carrier. It reuses the already-rendered source sample, has no runtime graph solver, cannot form a cycle, and keeps independent state per note. LFO modulation of PM depth stays in the block path.

AM, RM, and pan are intentionally not hidden inside PM fields. Each needs a persisted route mode, bounded musical depth, explicit UI, aliasing/gain tests, and proof that it reuses the source render. Feedback needs a deliberate one-sample delay, bounded loop gain, reset semantics, and hearing-safe output control.

Audio-rate oscillator destinations currently include Shape/Noise Color, Pulse/Noise Texture, pitch, level, pan, phase, Warp/Noise Stereo, jitter, stereo X/Y, Grain tune/stereo, Rich dynamic, and PM depth. All four filter controls are audio-rate. Discrete voice count, unison layout, random-start policy, and analysis-heavy resynthesis controls remain control-rate.
